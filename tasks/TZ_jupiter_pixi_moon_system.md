# ТЗ: полноэкранная интерактивная карта спутников Юпитера на PixiJS

## Контекст

Есть существующая страница `/planetarium/jupiter` (React), в ней секция `#moon-system` рендерит все известные спутники Юпитера на реальной линейной шкале орбит (SVG, ручной rAF-луп, `dotsRef.current` мутируется напрямую). Компонент: `src/pages/Jupiter.jsx` (или аналогичный путь в проекте).

Эта SVG-реализация остаётся как есть — лёгкий встроенный виджет на странице. Задача — сделать **отдельный полноэкранный режим** с более богатой навигацией, вынесенный в отдельный компонент, использующий PixiJS вместо SVG, без нагрузки на страницу вне этого режима.

Не трогать существующий `#moon-system` SVG-блок и его логику — только добавить новый компонент и точку входа в него (кнопка "Развернуть на весь экран" / fullscreen-иконка в контролах существующего блока).

## Цель

Полноэкранный (модалка или отдельный роут) интерактивный вид системы спутников Юпитера с:
- зумом к конкретному спутнику по клику/выбору,
- появлением реального фото спутника при достаточном приближении (LOD),
- подробной карточкой информации по клику на спутник,
- паузой/возобновлением анимации орбитального движения,
- переходом между спутниками (prev/next),
- приемлемой производительностью на слабом ПК (не проседать по FPS сильнее, чем текущий SVG-вариант, в идеале — заметно лучше).

## Технологии

- **PixiJS v7** (или v8, смотри по совместимости с остальным стеком проекта — уточнить версию React/сборщика перед установкой).
- Данные берутся из того же источника, что и текущий SVG-виджет: `useApi(getJupiter)` → `data.moons` (поля: `a_km`, `period_d`, `m0_deg`, `prograde`, `group`, `i_deg`, `e`, `diameter_km`, `name_uk`, и т.д. — сверить полный список полей в `services/jupiter` на бэкенде и задокументировать в коде компонента).
- Модель — **2D**, та же полярная система координат, что уже используется (`SYS.cx`, `SYS.cy`, `r`, угол по `m0_deg` + `360/period_d * t`). 3D-наклонение орбит (`i_deg`) в геометрии не используется — только в текстовой карточке, как и сейчас.

## Компонент и точка входа

Новый файл: `src/pages/JupiterMoonSystemFullscreen.jsx` (или `.tsx`, по конвенции проекта).

Открывается:
- либо как модалка поверх текущей страницы (предпочтительно — проще встроить, не плодит роуты, легко закрыть по Escape/клику вне),
- либо как отдельный роут `/planetarium/jupiter/system` — если в проекте уже принят паттерн полноэкранных под-страниц (посмотреть, как сделан лайтбокс `photo-modal` в текущем `Jupiter.jsx` — использовать аналогичный UX-паттерн: `Escape` закрывает, скролл body блокируется на время открытия).

Кнопка входа — рядом с существующими `.jup-sys-controls` (зум +/−/reset) в блоке `#moon-system`: добавить кнопку fullscreen с иконкой (лайфхак: переиспользовать существующие CSS-классы `.jup-sys-controls button`, не городить новый стиль с нуля).

## Архитектура рендера

Один `<canvas>` через `PixiJS Application`, вставленный в `useEffect` при монтировании компонента, уничтожаемый (`app.destroy(true, {children: true})`) при размонтировании — **обязательно**, иначе утечка WebGL-контекстов при повторных открытиях модалки.

Структура сцены (Pixi containers):
```
app.stage
 └─ world (Container)          // сюда применяется camera transform (x, y, scale)
     ├─ jupiterDisc (Sprite)   // диск планеты, true-scale как discR в текущем коде
     ├─ orbits (Container)     // 115+ Graphics-круги орбит, рисуются один раз, не перерисовываются каждый кадр
     └─ moons (Container)      // по одному Sprite/Container на спутник
         └─ moon[i]: Container { dot: Graphics | Sprite, label?: Text, photoSprite?: Sprite }
```

Мировые координаты спутников считаются **тем же способом**, что в текущем коде (`place(m, simDays)` из `Jupiter.jsx`), просто пишутся не в `cx/cy` SVG-атрибуты, а в `moon.position.set(x, y)` Pixi-объекта, в `app.ticker.add(...)`.

Камера — не трансформация viewBox (как в SVG), а `world.position` + `world.scale`, управляется отдельным state-объектом камеры (см. ниже). Орбиты и диск планеты рисуются один раз при загрузке данных (`Graphics`, не перерисовывать каждый кадр — только позиции точек-спутников меняются в тикере).

## Данные о фото и подробностях спутников

Для LOD "реальное фото при приближении" и карточки деталей нужен маппинг `moon.name → { photoUrl, details }`. **Честно ограничить: реальные фото есть только для спутников, где они реально существуют** (Галилеевы — Io/Europa/Ganymede/Callisto, у которых уже есть `/moons/{key}.jpg` в текущем коде; возможно ещё Amalthea, Himalia — по снимкам Galileo/Cassini, если такие есть в ассетах проекта). Для остальных ~100 мелких спутников фото физически не существует (нет разрешающих снимков) — агент не должен придумывать заглушки под видом "фото", вместо этого:
- при приближении к спутнику без реального снимка показывать иконку/плейсхолдер с подписью "фото недоступно — объект наблюдался только как точка света" (сформулировать корректно, без обмана пользователя),
- составить список `moonsWithRealPhotos` вручную (сверить с ассетами `/moons/*.jpg` и любыми доступными снимками иррегулярных спутников от JPL/Cassini, если такие фото будут добавлены в проект отдельно — это не входит в это ТЗ, agent не должен искать/скачивать фото сам без указания источника).

## Функциональность

### 1. Камера и зум к спутнику

Состояние камеры: `{ x, y, zoom }` (мировые координаты цели + масштаб), с плавным переходом (easing, ~600–800мс, cubic-in-out) между текущим и целевым состоянием, обновляется в `app.ticker`, не через CSS-transition (нужен контроль кадр-в-кадр для синхронизации с одновременным движением спутников).

```js
function easeInOutCubic(t) { return t < 0.5 ? 4*t*t*t : 1 - Math.pow(-2*t+2, 3)/2; }
```

По клику на спутник (или из карточки/списка) — камера анимированно летит к его текущей позиции и увеличивает zoom до порога, при котором виден LOD "фото" (см. ниже).

Свободный зум колесом мыши / pinch на тач-устройствах — центр зума в точке курсора (аналогично текущей SVG-реализации `onWheel` в `Jupiter.jsx`, тот же принцип, портировать на Pixi coordinates).
Панорамирование — drag (`pointerdown/move/up` на `app.stage`, `stage.eventMode = 'static'`, `hitArea` на весь canvas).

Ограничения зума: `zoomMin` (максимальное приближение — видно 1 спутник крупным планом) и `zoomMax` (видна вся система целиком, как дефолтный вид).

### 2. LOD (level of detail)

Пороги по `camera.zoom` (подобрать эмпирически, задокументировать константы в коде):
- далеко: спутник — точка (`Graphics`, circle), цвет по prograde/retrograde (переиспользовать `var(--teal)` / `var(--coral)` логику из текущего кода).
- средне: точка + текстовая подпись с именем (`PIXI.Text`, обновлять `visible`, не пересоздавать текст каждый кадр).
- близко (при фокусе на конкретном спутнике или сильном зуме рядом с ним): если есть реальное фото — заменить `dot` на `Sprite` с текстурой фото (использовать `PIXI.Assets.load` с кэшированием, не грузить текстуру повторно при каждом приближении); если фото нет — показать плейсхолдер с честной подписью (см. выше).

LOD-переключения делать через `visible`/текстуру, не через удаление-пересоздание объектов каждый кадр — держать все PIXI-объекты созданными один раз при инициализации сцены.

### 3. Карточка подробной информации

По клику на спутник (в любом LOD) — открывается HTML-оверлей (обычный React div поверх canvas, не Pixi-текст — читаемость и доступность важнее, копирование текста пользователем должно работать) с полями, аналогичными текущему SVG-тултипу (`jmt-row` блоки в `Jupiter.jsx`): группа, большая полуось, период, направление, наклонение, эксцентриситет, диаметр, плюс (если есть) короткое описание/фото покрупнее.

Клик по спутнику одновременно триггерит zoom-to-moon (см. п.1) — не два отдельных действия.

### 4. Пауза/возобновление вращения

Кнопка pause/play в UI полноэкранного режима. При паузе — зафиксировать `simDays` на момент паузы (аналогично текущему `TIME_SCALE`-подходу в коде), не просто останавливать `app.ticker` целиком, потому что тикер также двигает камеру во время анимации перелёта — не должно быть так, что пауза орбит блокирует полёт камеры к спутнику. Разделить: один флаг `orbitsPaused`, отдельно `cameraAnimating` — независимые состояния в одном тикере.

### 5. Навигация между спутниками (prev/next)

Список спутников уже отсортирован по группам (`ring → galilean → himalia → ananke → carme → pasiphae`, как в текущем `GROUPS`). Кнопки prev/next в UI полноэкранного режима переключают `focusedIndex` по этому списку и вызывают zoom-to-moon для нового индекса. Дополнительно (опционально, если не усложняет сильно) — выпадающий список/поиск по имени спутника для прямого перехода, учитывая что объектов ~115+.

### 6. Производительность

- Life-cycle тикера привязан к видимости компонента: `app.ticker.start()`/`stop()` по `IntersectionObserver` или просто по факту открытия/закрытия модалки (раз компонент существует только пока открыт полноэкранный режим — тикер работает всё время, пока он смонтирован, останавливается при размонтировании).
- Обязательна остановка по `document.visibilitychange` (вкладка в фоне) — `app.ticker.stop()`, resume при возврате фокуса.
- Orbits (`Graphics`) — статичны, рисуются один раз, не перерисовываются в тикере.
- Хиты по спутникам — через встроенный Pixi event system (`sprite.eventMode = 'static'`, `on('pointertap', ...)`), не через ручной расчёт расстояний в JS-цикле.
- Текстуры фото спутников грузить лениво (только при первом достижении LOD-порога, не все сразу при открытии модалки).

## Приёмочные критерии

1. Полноэкранный режим открывается и закрывается (кнопка + Escape), без утечек WebGL-контекста при многократном открытии/закрытии (проверить через DevTools Memory/Performance — число WebGL-контекстов не растёт).
2. Все спутники из `data.moons` отображаются на корректных орбитальных позициях, углы движения соответствуют текущей SVG-реализации (визуальная сверка — Io/Europa/Ganymede/Callisto должны идти синхронно с существующим виджетом на той же странице, если оба открыты для сравнения).
3. Клик на любой спутник → камера долетает до него плавно (600–800мс) → при достаточном зуме появляется фото (для Галилеевых спутников и других, где оно реально существует) или честный плейсхолдер (для остальных) → открывается карточка деталей с корректными данными по всем полям.
4. Пауза останавливает орбитальное движение, но не ломает перелёт камеры и не ломает возможность кликать/наводиться на спутники.
5. Prev/Next корректно листают список по порядку групп, зацикливаясь на концах.
6. Зум колесом/pinch центрируется в точке курсора/пальцев, панорамирование — drag.
7. FPS не проседает при полностью открытой модалке ниже приемлемого порога (замерить на слабом ноутбуке или через CPU throttling в DevTools — 4x slowdown должен давать ≥30 FPS).
8. Нет console-ошибок/warning от Pixi при монтировании/размонтировании.

## Вне рамок этого ТЗ

- 3D-визуализация с честными наклонёнными эллиптическими орбитами (возможное будущее развитие, не в этой итерации).
- Поиск/добыча реальных фотографий мелких иррегулярных спутников — это отдельная задача по контенту, агент не должен подставлять произвольные изображения под видом реальных снимков.
- Изменение существующего SVG-виджета `#moon-system` на странице — он остаётся как есть.
